# 单模型会话精简计划

## 决策

下一个版本将移除上游的**多模型并行回复**和**模型预设组**。Ayaka Chats 的每个会话在任一时刻只使用一个模型；用户可在聊天顶部切换模型，切换仅影响之后发出的消息，历史消息继续保留其实际使用的模型信息。

本次是直接切换，不设置兼容期，也不保留旧入口或旧 API 的兼容行为。已确认当前实例没有用户依赖多模型并行或模型预设组。

## 保留的能力

- 每个会话一个当前模型。
- 聊天顶部的模型选择器；模型可在会话进行中随时切换。
- 单模型的系统提示词、温度、最大输出 Token、推理强度、联网搜索、代码执行、MCP 和图像生成配置。
- 消息与会话配置快照中的模型信息，用于正确展示历史对话由哪个模型生成。

## 删除的产品能力

- 同一条用户消息向多个模型发送并同时展示多路回复。
- 模型启用/禁用开关、增加/移除会话模型，以及多模型消息分支选择。
- 模型预设组的创建、编辑、克隆、排序、应用与“重设模型”入口。
- 空白的“重设模型”弹窗及相关提示文案。

## 后端与数据

1. 保留 `ChatSpan`、`ChatConfig` 与 `ChatConfigSnapshot` 作为内部实现和历史记录，但在领域规则中强制每个 `Chat` 只有一个 `ChatSpan`。
2. 创建 EF Core SQLite migration：
   - 对意外存在多条 `ChatSpan` 的会话，仅保留已启用的最小 `SpanId`；若均未启用，则保留最小 `SpanId`。
   - 删除其余 `ChatSpan` 及无引用的 `ChatConfig` / `ChatConfigMcp`。
   - 删除 `ChatPreset`、`ChatPresetSpan`，以及只被预设组引用的 `ChatConfig` / `ChatConfigMcp`。
   - 删除预设组表及不再使用的索引和外键。SQLite 表重建必须通过 EF migration 完成，不能执行上游 SQL 脚本。
3. 简化会话创建、模型切换和发送请求：只读取和写入当前唯一 span。
4. 删除 `ChatPresetController`、预设组 DTO/请求模型、预设组 client API，以及创建/更新/删除额外 span 的会话 API。
5. 收紧消息、流式响应和消息树的查询与 DTO：不再把一个用户消息扩展为多个助手响应分支；移除面向多 span 的聚合逻辑。
6. 为数据库约束或服务层校验补充测试，确保无法为同一会话新增第二个 span。

## 前端

1. 重写 `ChatHeader`：显示当前模型名称和单一模型选择器；删除加号、模型组悬停操作、启停开关、删除模型按钮及“重设模型”齿轮。
2. `ChatModelSettingsModal` 改为编辑当前模型配置，不再接收或提供“移除模型”操作。
3. 删除以下组件及其调用链：
   - `ChatPresetList`
   - `ChatPresetModal`
   - `ChatPresetResetDialog`
   - 多模型专用的响应骨骼屏与消息分组 UI
4. 简化 `ChatView`、`ChatMessage`、`ChatInput`、模型能力判断和流式状态管理，使其基于单一当前模型。
5. 删除 `clientApis.ts`、类型定义、翻译资源中的预设组、多 span、重设模型相关接口和文案。

## 切换模型语义

- 模型选择器展示当前会话模型；选择新模型后立即保存会话配置。
- 不自动重跑、重写或删除已有消息。
- 下一条用户消息及其助手回复使用新模型和当前配置。
- 若新模型不支持当前配置项（例如 MCP、代码执行、视觉或推理强度），前端应禁用该项并在保存时清理无效配置，后端也必须验证。

## 验收标准

- 新建会话和任何已有会话均恰好有一个可用模型。
- 顶部可切换模型；切换后的下一轮请求只调用一个模型。
- 页面中不再出现模型预设组、添加模型、启停模型或重设模型入口。
- 普通对话、临时聊天、联网搜索、代码执行、MCP、图像生成、消息编辑/重新生成与历史消息展示均可正常工作。
- 后端测试、前端 lint/type check 通过；空库与升级库均能由 `Database.MigrateAsync` 完成升级。

## 非目标

- 本版本不实现类似 ChatGPT 的全局“模型配置预设”。如后续确有需求，应设计为单模型参数模板，不能重新引入模型组或并行回复语义。

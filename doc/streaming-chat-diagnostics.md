# 流式聊天中断排查

HTTP 200 和后端没有异常，不能证明浏览器完整收到或显示了回复。排查时分别确认模型结束事件、服务端最终消息事件、浏览器的接收与渲染状态。

## 客户端诊断

登录用户的异常通过 `POST /api/client-diagnostics/chat` 上报。后端日志搜索 `Client chat diagnostic`，再用 `RequestTraceId` 对应请求追踪的 `TraceId`。

| Stage | 含义 |
| --- | --- |
| `render` | 聊天组件渲染或 effect 抛错，由聊天错误边界捕获 |
| `stream-read` | 请求建立或响应流读取失败 |
| `stream-parse` | SSE data 无法解析或缺少事件类型 |
| `stream-incomplete` | 响应体为空，或 EOF 时缺少最终消息/leaf 事件、残留不完整数据 |

诊断包含会话 ID、前端版本、请求 TraceId、StopId、已解析事件数量、最后的事件类型、异常类型和代码栈。客户端不发送异常消息、聊天正文或原始 SSE；解析异常消息可能含有正文片段，因此刻意省略。每页每分钟最多发送 10 条，接口要求登录并限制请求和字段长度。上报失败不影响聊天恢复。

服务端在聊天 SSE 响应头提供 `X-Chat-Trace-Id`，开发环境 CORS 暴露该头。旧服务端没有这个头时，仍可用会话 ID、StopId 和时间定位。

生成过程导致输入框自动收起后，聊天组件异常卸载会丢失组件内的自动恢复标记。错误边界捕获异常时恢复全局输入框展开状态，使重新加载或切换会话后能继续输入。这个恢复修复不代表所有渲染异常的触发原因已解决。

## 1.17.13 部署后的继续排查

### 输入框移出视口

使用合成长历史消息复现：Ctrl+Enter 模式下按 Enter 只插入换行，发送请求数量为 0，但聊天区域的 flex 子项默认最小高度受消息内容影响，超过父容器的视口高度。绝对定位在底部的输入框因此移出屏幕。输入区高度对应的消息尾部占位又参与容器高度计算，使溢出继续扩大。此类布局错误没有抛异常，不会触发 `render` 诊断。

修复聊天视图 flex 子项的 `min-h-0`，并约束首页内部 flex 容器，使消息在自己的滚动区域中滚动。修复前，900px 视口内的输入框顶部可超过 4000px；修复后聊天区域保持 900px，输入框顶部为 725px。回归检查必须比较输入框边界与视口，单独检查 DOM 存在或 `isVisible()` 不足以发现这个问题。

### Service Worker 安装失败

`next-pwa` 默认预缓存了 Next.js 构建生成的 `dynamic-css-manifest.json`，但静态导出的 `out/_next/` 中没有该文件。请求返回 404，Workbox 中止安装。通过 `buildExcludes` 排除该清单，继续缓存实际发布的静态资源。这个错误证明新 worker 安装失败，尚不能证明它引起了响应流断开。

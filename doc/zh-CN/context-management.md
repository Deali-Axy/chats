# 上下文管理

聊天输入区的「上下文剩余」按钮可查看当前模型的上下文窗口、估算用量、系统提示词、工具定义、对话摘要、保留的历史、当前草稿及预留输出空间。多模型聊天可以在面板内切换模型，每个模型独立保存设置和摘要。

用量是估算值，包含输入草稿；不同服务商的分词和附件计费方式可能不同。模型管理中的上下文窗口应与实际服务商限制一致。图像生成模型不使用此功能。

## 自动压缩

默认开启自动压缩，保留至少最近 **6 条消息**（用户或助手消息各计一条）。每次向模型发送请求前，包括工具执行后续轮次，都会检查预算：

- 为模型输出预留配置的最大输出 tokens；未配置时，预留窗口的 1/8，最低 256、最高 8,192 tokens。
- 另留窗口的 5% 作为估算余量，最低 32、最高 4,096 tokens。
- 达到剩余输入预算的 **80%** 时，将较早的完整对话归纳成摘要。系统提示词、最近消息和当前正在执行的工具调用链保持完整。

压缩只能在完整的用户/助手交换结束处切分，不拆开工具调用与结果；为满足这个条件，实际保留消息数可能更多。后续压缩会合并已有摘要与新产生的历史。已超出窗口的历史会分块生成摘要。

开始压缩时界面显示进度，完成后会提示压缩成功，并持续标记已归纳的消息数量。摘要保留目标、约束、重要决定、工具结果、错误和待办事项，但可能损失细节。较早附件以引用参与归纳，附件原文件不会作为摘要请求的输入。

摘要使用当前聊天模型，通过正常模型用量计费（`Summary` 来源）。压缩不删除聊天记录；原始消息和文件仍可在会话中查看。

## 手动操作

在输入区打开上下文面板：

1. **立即压缩**：不必等到自动阈值，即可归纳较早的完整对话。生成期间禁止发送新消息，可取消。
2. **自动压缩开关**：关闭后保留当前摘要，但不继续自动压缩。
3. **保留最近消息数**：可选 2、4、6、8、12、20。增加数量会先恢复完整历史，再按新策略进行后续压缩。
4. **查看对话摘要**：查看摘要全文、生成时间和压缩前后 tokens。
5. **恢复完整上下文**：清除活动摘要，并关闭自动压缩，避免下一条消息立即又被归纳。

设置和摘要随会话保存。切换分支或编辑较早消息时，会验证摘要的来源；不匹配的摘要不会发送给模型。

## 从摘要创建新对话

在上下文面板点击 **从摘要创建新对话**，可以查看并编辑要带入的摘要和新对话标题，再点击 **创建并继续**。

- **复用现有摘要**不调用模型。现有压缩摘要只覆盖较早消息，界面会提醒最近进展尚未包含，可手动补充。
- **生成交接摘要**将已有摘要和当前分支的最近对话合并；未压缩的会话也能使用。此操作按当前模型产生摘要用量，不修改来源对话的活动摘要。生成过程以流式方式保持连接，避免网关空等超时；摘要文本会逐步写入编辑框。
- 新对话继承所选模型、提示词、工具配置、上下文设置及分组，作为普通持久化对话保存。即使来源是临时对话，新对话也会保留。
- 摘要成为新对话的第一条可见消息，附有来源对话链接，并显示摘要已载入的提示。创建过程不会让模型自动回复，发送下一条请求后即可继续工作。
- 原始消息、附件、Docker/工具运行会话及未发送草稿留在来源对话。摘要内的文件和工具引用是背景信息，需要时应重新提供文件或启动工具。
- 生成期间可以取消；若来源消息在预览后被编辑，或编辑后的摘要超出模型预算，创建会被拒绝，需要重新生成/加载或缩短摘要。

## 无法压缩时

摘要生成失败、未降低用量，或保留内容仍超出预算时，保留原上下文并显示错误。原输入还在预算内时，自动压缩失败后可继续回答；超过预算时，会阻止发送过大的模型请求。

当前消息、系统提示词、工具定义或一个完整工具调用链本身过大时，仅压缩历史无法解决。可以减少保留消息数、缩短输入/工具输出，或选择上下文窗口更大的模型。

## 数据库升级

本功能由 `AddChatContextManagement` EF Core migration 给 `ChatSpan` 增加设置与摘要检查点。空库及已有本 Fork 1.12+ SQLite 库启动后端时自动升级，不需要手工 SQL。1.11 及更早数据库仍须走 `tools/DataMigration`。
